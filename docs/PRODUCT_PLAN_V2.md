# StockDash v2.0 제품 기획서

> 상태: 기획 확정 전 초안
> 대상 저장소: `planxs-ai/stock-dash`
> 목적: 단순 종목 분석 앱을 기관 API 확장형 투자 데이터 허브로 재설계
> 원칙: 실데이터와 가설을 분리하고, 데이터 출처·기준일·신뢰도를 화면에 명시한다.

---

## 1. 제품 한 줄 정의

**StockDash는 시장 → 산업 → 기업 → 가치 → 수급 → 공시 → 판단을 한 화면 흐름으로 연결하는 개인 투자 분석 워크스테이션이다.**

현재 앱은 종목명 검색, 공공데이터포털 시세, OpenDART 재무/공시, 간단한 성장·수익성·가치 점수, 관심종목 저장 기능을 제공한다.

v2의 목표는 여기에 기관 API를 플러그인 방식으로 추가해, API가 늘어날수록 기능이 자연스럽게 확장되는 구조를 만드는 것이다.

---

## 2. 해결하려는 핵심 문제

### 현재 문제

1. 기능 대부분이 `app.py` 단일 화면에 모여 있어 확장성과 유지보수성이 낮다.
2. 데이터 공급자 로직과 UI가 강하게 결합되어 기관 API를 추가할 때 수정 범위가 커진다.
3. 사용자는 데이터를 보더라도 "그래서 지금 무엇을 봐야 하는가"가 한눈에 연결되지 않는다.
4. 시세·공시·재무는 있으나 시장, 수급, 산업, 수출, 거시경제 등 투자 판단의 앞단 데이터가 부족하다.
5. API 오류와 데이터 미수집이 화면 기능 실패로 직접 전파된다.
6. 현재 점수는 규칙 기반 참고값이며 검증된 예측 모델이 아니다. 따라서 점수보다 근거 데이터와 변화 방향을 중심으로 보여줘야 한다.

### v2 해결 방향

- **API Adapter Layer**: 기관별 API를 동일 인터페이스로 연결
- **Capability Registry**: 어떤 데이터가 연결되었는지 자동 인식
- **Feature Modules**: 시장/종목/공시/수급/섹터/포트폴리오를 독립 모듈화
- **Evidence Card**: 모든 핵심 카드에 출처, 기준일, 실데이터/추정 구분 표시
- **Decision Flow**: 데이터 나열이 아니라 투자 판단 순서대로 화면 구성

### 좌측 내비게이션

7. **관심 종목**

9. **데이터 연결 관리**

### 상단 공통 검색

검색 대상:
- 종목명
- 종목코드

```python
{

  "name": "삼성전자",
  "market": "KOSPI",
  "source": "기관명",
  "matched_by": "name"
}
```

## 4. 승인된 디자인 방향

기존 샘플의 **프레임 구조는 유지**하고 배경을 밝게 사용한다.

### 디자인 키워드

- 밝고 깨끗한 금융 데이터 화면
- White / Warm White 기반
- 얇은 회색 경계선
- 카드 중심 레이아웃
- 강한 그림자 금지
- 핵심 행동만 Blue Accent
- 상승 Green / 하락 Red
- 데이터 밀도는 높되 여백 확보

### 기본 레이아웃

- 좌측 고정 사이드바: 230~250px
- 상단 검색바: 최대폭 640px
- 본문: 12-column grid
- 카드 radius: 14~18px
- 카드 border: `#E6EAF0`
- 배경: `#F7F9FC` 또는 `#FAFBFD`
- 본문 카드: `#FFFFFF`
- Primary: `#2563EB`
- Text Primary: `#0F172A`
- Text Secondary: `#64748B`
- Positive: `#10B981`
- Negative: `#EF4444`

### 첫 화면 구성

1. Hero / 오늘의 시장 요약
2. 국내·해외 주요 지수 카드
3. 주요 지수 추이 차트
4. 오늘의 주요 뉴스/공시
5. 상승률 TOP / 거래대금 TOP
6. AI 투자 인사이트
7. 관심종목 변화 알림

기관 API가 아직 연결되지 않은 카드는 **빈 가짜 숫자를 표시하지 않고** `데이터 연결 필요` 상태로 노출한다.

## 5. 핵심 사용자 흐름

### A. 홈

목적: 30초 안에 오늘 시장과 내 관심종목의 변화를 파악

표시:
- KOSPI / KOSDAQ
- 원달러 환율
- 미국 주요 지수
- 시장 거래대금
- 외국인/기관 순매수
- 오늘 가장 중요한 공시
- 관심종목 이벤트
- AI 요약

### B. 시장 현황

목적: 시장이 위험선호인지 위험회피인지 판단

후보 기능:
- 지수 등락
- 거래대금
- 상승/하락 종목 수
- 투자자별 순매수
- 업종 등락률
- 환율/금리
- 프로그램 매매
- 신용잔고/공매도
- 변동성 지표

### C. 종목 분석

목적: 한 기업의 투자 판단 근거를 한 화면에 통합

섹션 순서:

1. 기업 특징
2. 현재 가격/52주 위치
3. 실적 추이
4. 성장률
5. 수익성
6. 밸류에이션
7. 수급
8. 공시/뉴스
9. 산업 데이터
10. 리스크
11. AI 핵심 요약
12. 투자 메모

### D. 공시 분석

- 최근 공시
- 실적 발표
- 수주
- 증자/전환사채
- 지분 변화
- 배당
- 자사주
- 신규시설투자
- 공급계약
- 공시 중요도 분류
- 이전 공시와 변화 비교

### E. 테마 & 섹터

목적: 종목이 아니라 산업 흐름부터 탐색

- 업종 상승률
- 거래대금 증가
- 외국인/기관 유입
- 수출 증가
- 수주 증가
- 실적 상향
- 주요 관련주
- 시장 주도 강도

### F. 포트폴리오

- 보유종목
- 평균단가
- 수익률
- 비중
- 섹터 집중도
- 손익기여도
- 이벤트 일정
- 리스크 경고

자동 주문 기능과는 분리한다.

### G. 관심종목

- 관심종목 목록
- 최신 가격
- 최근 공시
- 실적 변화
- 목표 체크포인트
- 마지막 분석일
- 재점검 필요 상태

### H. AI 인사이트

AI는 숫자를 생성하지 않고 **수집된 데이터의 변화와 의미를 해설**한다.

권장 출력 구조:

- 무엇이 변했는가
- 왜 중요한가
- 어떤 숫자를 추가 확인해야 하는가
- 기존 투자 논리를 강화/약화하는가
- 다음 확인 이벤트

## 6. 기관 API 확장 구조

### 핵심 원칙

기관별 API를 UI에서 직접 호출하지 않는다.

```text
기관 API
   ↓
Adapter
   ↓
Normalizer
   ↓
Cache / Store
   ↓
Feature Service
   ↓
UI Card
```

### Adapter 공통 인터페이스

```python
class DataProvider:
    provider_id: str
    provider_name: str

    def health(self) -> dict: ...
    def capabilities(self) -> list[str]: ...
    def fetch(self, capability: str, **params) -> dict: ...
```

### 표준 Capability 예시

```text
market.index
market.breadth
market.turnover
market.investor_flow
market.short_selling
market.program_trade
macro.fx
macro.rate
stock.quote
stock.profile
stock.financials
stock.valuation
stock.investor_flow
stock.short_selling
stock.disclosures
stock.news
stock.consensus
sector.performance
sector.flow
industry.export
industry.order
portfolio.quote
```

기관 API를 제공받으면 "API 이름"이 아니라 **어떤 capability를 채울 수 있는지** 먼저 판별한다.

## 7. API 연결 관리 화면

새 메뉴: **데이터 연결 관리**

기관별 카드에 다음을 표시한다.

- 기관명
- 연결 상태
- 인증 상태
- 마지막 정상 호출
- 응답 시간
- 사용 가능 기능
- 데이터 최신 기준일
- 호출 제한
- 오류 메시지

예시:

```text
OpenDART
● 정상
기업개황 / 재무 / 공시 / 사업보고서
마지막 확인: 2026-09-09 19:42

금융위원회 주식시세정보
● 정상
종목검색 / 일별시세
기준일: 2026-09-09
```

API 키 자체는 화면에 표시하지 않는다.

## 8. 기관 API를 받았을 때 검토 표준

각 API마다 아래 10개 항목을 기록한다.

| 항목 | 검토 내용 |
|---|---|
| 기관 | 제공 기관 |
| API | 서비스명 |
| 인증 | 키/OAuth/IP 제한 |
| 데이터 | 제공 필드 |
| 빈도 | 실시간/분/일/월 |
| 기준일 | 데이터 기준 시점 |
| 한도 | 일/분 호출 제한 |
| 비용 | 무료/유료 |
| 저장 | 재배포/DB 저장 가능 여부 |
| Capability | StockDash에서 연결 가능한 기능 |

그리고 기능을 세 등급으로 분류한다.

- **P0 핵심**: 사용자 판단 흐름을 직접 개선
- **P1 강화**: 분석 정확도/편의 증가
- **P2 선택**: 시각화나 참고 기능

## 10. 데이터 신뢰도 표시

모든 주요 데이터는 아래 메타데이터를 가진다.

```python
{
  "value": 12345,
  "source": "KRX",
  "as_of": "2026-09-09",
  "fetched_at": "2026-09-09T19:30:00+09:00",
  "status": "official",
  "stale": false
}
```

화면 라벨:

- 공식 데이터
- 공시 데이터
- 계산값
- AI 해설
- 데이터 지연
- 데이터 없음

AI 생성값을 공식 데이터처럼 표시하지 않는다.

## 12. 구현 단계

### Phase 1 — UI Shell

목표: 승인된 밝은 대시보드 프레임 구현

- 좌측 내비게이션
- 상단 검색
- 공통 카드 스타일
- 홈 화면
- 반응형 레이아웃
- 기존 기능 연결 유지

완료 기준:
- 기존 검색/분석 기능이 유지됨
- 모바일/PC 모두 사용 가능
- 샘플 이미지와 정보 계층이 유사함

### Phase 2 — Provider Registry

목표: 기관 API를 추가할 수 있는 기반

- Provider Base
- Capability Registry
- Health Check
- Error isolation
- 캐시 인터페이스

완료 기준:
- OpenDART와 현재 공공데이터 API가 Registry를 통해 호출됨
- 데이터 연결 관리 화면에서 상태 확인 가능

### Phase 3 — Market Dashboard

기관 API가 제공되면 가능한 기능부터 연결

우선:
- 지수
- 시장 breadth
- 거래대금
- 투자자 수급
- 업종

### Phase 4 — Stock 360

- 기업 기본정보
- 실적
- 밸류
- 수급
- 공시
- 산업
- AI 요약

### Phase 5 — Decision Engine

분석 결과를 단순 점수 대신 근거 기반 상태로 표시

예:

```text
성장       개선
수익성     유지
밸류       과거 범위 하단
외국인수급 3일 연속 개선
공시       중요 변화 없음
산업       수출 증가
```

이 단계의 판단 규칙은 실데이터로 검증하기 전까지 투자 성과 예측 모델로 표현하지 않는다.

## 14. 성공 기준

### 기술 성공

- 새 기관 API Adapter를 기존 화면 코드 수정 없이 등록 가능
- 하나의 API 장애가 전체 앱을 멈추지 않음
- 모든 카드가 출처/기준일을 추적 가능

### 사용자 성공

사용자가 한 종목을 검색한 후 3분 안에 다음 질문에 답할 수 있어야 한다.

1. 이 기업은 무엇을 하는가?
2. 실적은 좋아지고 있는가?
3. 현재 가격은 과거 대비 어떤 위치인가?
4. 누가 사고 있는가?
5. 최근 중요한 공시는 무엇인가?
6. 산업 흐름은 좋아지고 있는가?
7. 다음에 무엇을 확인해야 하는가?

## 15. 구현하지 않을 것

초기 v2에서 제외:

- 자동 주문
- 검증되지 않은 매수/매도 신호
- AI가 만든 임의 목표주가
- 출처 없는 뉴스 요약
- API 미연결 구간의 가상 실데이터
- 모든 데이터를 하나의 종합점수로 강제 압축
